# Scale run on PostgreSQL

Generated by `python -m tasleem.loadtest --patients 5000 --db postgresql+psycopg://...` on 16 Nov 2026, with the workflow layer (assignments + outbox written on every case change).
Synthetic patients only. One process, PostgreSQL 16 in Docker Desktop on Windows (WSL2), API in a container, no Redis. This is a floor for one API
replica on a laptop, not a cluster benchmark. Production runs on PostgreSQL with several replicas.

What scales with what: ingest cost is per message and did not grow with case count; worklist and
detail reads are index-backed and flat; the metrics scan is linear in cases but cached, with staleness
bounded at 15 s by default, so it runs at most a few times a minute regardless of dashboard traffic.
Only FIT-positive results open a case, so live open-case counts are a small fraction of people screened.
Bulk backfills are the load to plan for: run them through the queue (TSL-045) with several workers.

**Read against demand.** Abu Dhabi produces on the order of 200,000 actionable screening results a year (planning assumption, not a DoH figure). At about 7 messages per case, that is ~1.4 million messages a year, or **about 0.05 messages a second on average**. One replica on a laptop handled 51.8 a second: roughly 1,000× headroom before adding replicas, which the design allows (stateless API, per-case optimistic locks, `SKIP LOCKED` scheduler).

**Compared with SQLite** ([SCALE.md](SCALE.md), ~235 messages/s): Postgres here pays a network round trip per statement through Docker Desktop's VM, and every case write now also rebuilds its assignments and appends outbox rows. The worklist p95 (220 ms) is the number to improve first if needed: it reads full state documents; a slimmer projection column would cut it.
